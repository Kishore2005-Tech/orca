# ORCA API Specification

REST API for ORCA (SIH26176). This specification implements the endpoints needed to support the PRD's MVP scope (see `WORKFLOW.md` § MVP Priority Rule), the agent contracts in `AGENT_CONTRACTS.md`, and the tables in `DATABASE_SCHEMA.md`. Field names below are chosen to match those documents directly — an endpoint's response is, wherever possible, a thin serialization of an existing table row or agent envelope, not a parallel schema invented for the API layer.

**Base URL:** `https://api.orca.example/v1`
**Format:** JSON request/response bodies (`application/json`), except `map` responses which use GeoJSON (`application/geo+json`).

---

## 1. Global Conventions

### 1.1 Authentication

Two auth modes, applied per endpoint below:

| Mode | Mechanism | Used for |
|---|---|---|
| `public` | API key, header `X-API-Key: <key>` | Read-only environmental/reference data (observations, PFZ, map) — no user account required |
| `authenticated` | Bearer JWT, header `Authorization: Bearer <token>` | Anything that invokes the agent pipeline, or reads data scoped to a specific request/user (query, recommendations, evidence, per-request agent status) |
| `internal` | Bearer JWT with `role: admin` claim | Operational agent-health monitoring |

If `users` (per `DATABASE_SCHEMA.md` §2.10) is not deployed for a given prototype build, `authenticated` endpoints fall back to an anonymous session token issued per browser session — the auth *mode* still applies, only the identity behind it changes.

### 1.2 Rate Limiting

| Tier | Applies to | Limit | Header returned |
|---|---|---|---|
| `public-read` | observation/PFZ/map endpoints | 120 req/min per API key | `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` |
| `query-pipeline` | `POST /query` | 15 req/min per user (invokes the full multi-agent pipeline — expensive) | same headers |
| `authenticated-read` | evidence, recommendations, per-request agent status | 60 req/min per user | same headers |
| `internal` | agent health monitoring | 300 req/min | same headers |

Exceeding a limit returns `429 Too Many Requests` with the standard error envelope (§1.4) and a `Retry-After` header.

### 1.3 Pagination

Two conventions, chosen per data shape:

- **Cursor-based** (time-series and evidence — large, naturally time-ordered collections): query params `limit` (default 50, max 200) and `cursor` (opaque, base64-encoded). Response includes `"next_cursor": string | null`.
- **Offset-based** (small, bounded collections — PFZ zones, recommendations list): query params `limit` (default 20, max 100) and `offset` (default 0). Response includes `"total_count": number`.

### 1.4 Error Envelope

Every error response uses this shape:
```json
{
  "error": {
    "code": "string (e.g. ORCA_API_ERR_VALIDATION)",
    "message": "string, human-readable",
    "details": "object | null (field-level info, e.g. which parameter failed validation)"
  }
}
```

**Shared API error codes** (in addition to the domain `ORCA_ERR_*` codes from `AGENT_CONTRACTS.md`, which are surfaced verbatim inside `details` when a domain agent's error propagates to the API):

| Code | HTTP status | Meaning |
|---|---|---|
| `ORCA_API_ERR_VALIDATION` | 400 | Request failed schema/parameter validation |
| `ORCA_API_ERR_AUTH` | 401 | Missing/invalid credentials |
| `ORCA_API_ERR_FORBIDDEN` | 403 | Valid credentials, insufficient scope |
| `ORCA_API_ERR_NOT_FOUND` | 404 | Resource does not exist |
| `ORCA_API_ERR_RATE_LIMIT` | 429 | Rate limit exceeded |
| `ORCA_API_ERR_PIPELINE_TIMEOUT` | 504 | Agent pipeline exceeded its overall timeout budget (`AGENT_CONTRACTS.md` Coordinator `TIMEOUT`: 20000ms) |
| `ORCA_API_ERR_UPSTREAM_UNAVAILABLE` | 503 | A required agent/data source is unavailable (maps to `ORCA_ERR_SOURCE_UNAVAILABLE`) |
| `ORCA_API_ERR_INTERNAL` | 500 | Unhandled server error |

### 1.5 Standard Headers

Every response includes `X-Request-Id` (matches `request_id` from `AGENT_CONTRACTS.md`'s envelope, generated by the API if not supplied by the client) so that any response can be traced back to its full agent execution trace via §2.10.

## 2. Endpoints

### 2.1 ORCA Query — the main pipeline entry point

**`POST /api/v1/query`**

Invokes the full Coordinator pipeline (`REASONING_FRAMEWORK.md` §11) and returns the final composed answer (`AGENT_CONTRACTS.md` §8 Coordinator OUTPUT SCHEMA).

- **Auth:** `authenticated`
- **Rate limit:** `query-pipeline` tier

**Request schema**
```json
{
  "request_id": "string (uuid v4, optional — server generates if omitted)",
  "user_query": "string, required, 1-2000 chars",
  "conversation_context": [
    { "role": "enum[user, assistant]", "content": "string" }
  ]
}
```

**Response schema** (`200 OK`)
```json
{
  "request_id": "string (uuid)",
  "timestamp": "string (ISO 8601)",
  "final_answer": "string",
  "contributing_agents": ["enum[ocean, ecosystem, fisheries, safety, geospatial, knowledge_rag, verification, coordinator]"],
  "verification_verdict": "enum[pass, pass_with_caveats, fail]",
  "final_confidence": { "level": "enum[high, medium, low]", "score": "number", "basis": "string" },
  "citations": [ "EvidenceItem, see AGENT_CONTRACTS.md §0" ],
  "caveats": ["string"],
  "unresolved_conflicts": [ { "claim_a": "string", "claim_b": "string", "source_a": "string", "source_b": "string" } ]
}
```

**Validation**
- `user_query` required, non-empty, ≤ 2000 chars.
- `conversation_context`, if present, ≤ 20 messages.

**Errors**
| Status | Code | Condition |
|---|---|---|
| 400 | `ORCA_API_ERR_VALIDATION` | Empty/oversized `user_query` |
| 401 | `ORCA_API_ERR_AUTH` | Missing/invalid token |
| 429 | `ORCA_API_ERR_RATE_LIMIT` | Rate limit exceeded |
| 503 | `ORCA_API_ERR_UPSTREAM_UNAVAILABLE` | A required agent could not be reached |
| 504 | `ORCA_API_ERR_PIPELINE_TIMEOUT` | Pipeline exceeded 20000ms budget |
| 500 | `ORCA_API_ERR_INTERNAL` | Unhandled error |

**Pagination:** not applicable (single result).

**Example request**
```http
POST /api/v1/query
Authorization: Bearer eyJhbGciOi...
Content-Type: application/json

{
  "user_query": "Is it safe to go fishing near Kanyakumari today?"
}
```

**Example response**
```json
{
  "request_id": "5c2e6a3e-2b1d-4f2a-9c3d-1a2b3c4d5e6f",
  "timestamp": "2026-08-31T09:12:00Z",
  "final_answer": "An active small-craft advisory is in effect near Kanyakumari due to high wave conditions — conditions are considered dangerous. The recreational fishing season for this area is currently open, but that does not override the safety advisory. No positive fishing recommendation is issued at this time.",
  "contributing_agents": ["geospatial", "ocean", "fisheries", "safety", "verification", "coordinator"],
  "verification_verdict": "pass",
  "final_confidence": { "level": "high", "score": 0.91, "basis": "active verified Tier-1 advisory, fresh" },
  "citations": [
    { "source": "Indian National Centre for Ocean Information Services", "source_type": "advisory_feed", "reference": "incois-small-craft-2026-08-31", "observed_or_published_at": "2026-08-31T06:00:00Z", "retrieved_at": "2026-08-31T09:11:50Z", "passage_or_value": "extreme" }
  ],
  "caveats": ["Fisheries season status is informational only and does not indicate current safety."],
  "unresolved_conflicts": []
}
```

### 2.2 Marine Observations (generic)

**`GET /api/v1/observations`**

Backs `marine_observations` (`DATABASE_SCHEMA.md` §2.3) directly. This is the base endpoint; §2.3–2.7 below are thin, parameter-fixed conveniences over the same underlying table (per `DATABASE_SCHEMA.md` §4's "one table, not five" rationale).

- **Auth:** `public`
- **Rate limit:** `public-read`

**Request (query params)**
| Param | Type | Required | Notes |
|---|---|---|---|
| `parameter` | enum (see `observation_parameter`) | yes | e.g. `sst`, `wave_height`, `chlorophyll_a` |
| `lat`, `lon` | number | one of `lat/lon`, `location_id`, or `region_name` required | point query |
| `radius_m` | number | no, default 10000 | used with `lat/lon` |
| `location_id` | uuid | see above | direct location reference |
| `region_name` | string | see above | resolved via Geospatial Agent |
| `start`, `end` | ISO 8601 | no, default: last 24h | time range |
| `quality` | enum | no | filter by `verified/provisional/estimated/flagged` |
| `limit`, `cursor` | — | no | pagination, §1.3 |

**Response schema** (`200 OK`)
```json
{
  "data": [
    {
      "id": "uuid",
      "location": { "id": "uuid", "canonical_name": "string", "lat": "number", "lon": "number" },
      "parameter": "string",
      "value": "number",
      "unit": "string | null",
      "depth_m": "number | null",
      "observed_at": "string (ISO 8601)",
      "is_forecast": "boolean",
      "source": "string",
      "dataset": "string",
      "quality": "enum[verified, provisional, estimated, flagged]"
    }
  ],
  "next_cursor": "string | null"
}
```

**Validation:** `parameter` must be a known enum value; at least one location selector required; `start < end`.

**Errors**
| Status | Code | Condition |
|---|---|---|
| 400 | `ORCA_API_ERR_VALIDATION` | Missing/invalid `parameter` or location selector |
| 404 | `ORCA_API_ERR_NOT_FOUND` | `location_id` does not exist |
| 429 | `ORCA_API_ERR_RATE_LIMIT` | — |

Note: an empty result set for a valid query is `200 OK` with `"data": []`, not a `404` — absence of data is a valid answer, not an error (`EVIDENCE_AND_CONFLICT_FRAMEWORK.md` §B.6).

**Example request**
```
GET /api/v1/observations?parameter=sst&lat=8.08&lon=77.55&radius_m=20000&limit=10
X-API-Key: pub_live_abc123
```

**Example response**
```json
{
  "data": [
    {
      "id": "a1b2c3d4-0000-0000-0000-000000000001",
      "location": { "id": "loc-001", "canonical_name": "Kanyakumari Coastal Buoy", "lat": 8.08, "lon": 77.55 },
      "parameter": "sst",
      "value": 29.4,
      "unit": "degC",
      "depth_m": 0,
      "observed_at": "2026-08-31T08:00:00Z",
      "is_forecast": false,
      "source": "INCOIS",
      "dataset": "Coastal Buoy Network",
      "quality": "verified"
    }
  ],
  "next_cursor": null
}
```

### 2.3 SST

**`GET /api/v1/sst`** — identical shape to §2.2 with `parameter` fixed to `sst`; all other query params, response schema, validation, errors, and pagination are as in §2.2.

### 2.5 Currents

**`GET /api/v1/currents`** — composes the two related `marine_observations` parameters (`current_speed`, `current_direction`) sharing the same `location_id` and `observed_at` into one record, since a current reading is only meaningful as a speed+direction pair.

- **Auth:** `public` · **Rate limit:** `public-read`

**Response schema** (`200 OK`)
```json
{
  "data": [
    {
      "location": { "id": "uuid", "canonical_name": "string", "lat": "number", "lon": "number" },
      "speed_ms": "number",
      "direction_deg": "number",
      "depth_m": "number | null",
      "observed_at": "string (ISO 8601)",
      "is_forecast": "boolean",
      "source": "string",
      "dataset": "string",
      "quality": "enum[verified, provisional, estimated, flagged]"
    }
  ],
  "next_cursor": "string | null"
}
```
**Validation:** identical location/time params as §2.2. If only one of the two underlying parameters is available for a given location/timestamp, that record is omitted (not returned with a null half — an incomplete current reading is not returned as if complete), and this is noted in a `warnings` array alongside `data`.

**Errors:** as §2.2, plus `200 OK` with a `"warnings"` array when partial pairs were excluded.

**Example request:** `GET /api/v1/currents?lat=8.08&lon=77.55&radius_m=20000`

### 2.6 Waves

**`GET /api/v1/waves`** — composes `wave_height`, `wave_period`, `wave_direction` into one record per location/timestamp, same pairing logic as §2.5.

- **Auth:** `public` · **Rate limit:** `public-read`

**Response schema** (`200 OK`)
```json
{
  "data": [
    {
      "location": { "id": "uuid", "canonical_name": "string", "lat": "number", "lon": "number" },
      "height_m": "number",
      "period_s": "number | null",
      "direction_deg": "number | null",
      "observed_at": "string (ISO 8601)",
      "is_forecast": "boolean",
      "source": "string",
      "dataset": "string",
      "quality": "enum[verified, provisional, estimated, flagged]"
    }
  ],
  "next_cursor": "string | null"
}
```
`height_m` is required for a record to be returned; `period_s`/`direction_deg` are nullable since they may not always be co-reported.

### 2.8 PFZ (Potential Fishing Zones)

**`GET /api/v1/pfz`** — active/historical PFZ advisories, backed by `pfz_zones` (`DATABASE_SCHEMA.md` §2.4).

- **Auth:** `public` · **Rate limit:** `public-read`

**Request (query params)**
| Param | Type | Required | Notes |
|---|---|---|---|
| `lat`, `lon` | number | no | point-containment filter |
| `bbox` | `minLon,minLat,maxLon,maxLat` | no | bounding-box filter |
| `active_only` | boolean | no, default `true` | filters to `now() BETWEEN valid_from AND valid_until` |
| `limit`, `offset` | — | no | pagination, §1.3 |

**Response schema** (`200 OK`, GeoJSON-embedded)
```json
{
  "data": [
    {
      "id": "uuid",
      "geometry": "GeoJSON Polygon",
      "generated_at": "string (ISO 8601)",
      "valid_from": "string (ISO 8601)",
      "valid_until": "string (ISO 8601)",
      "issuing_source": "string",
      "basis_parameters": ["sst", "chlorophyll_a"],
      "advisory_text": "string | null"
    }
  ],
  "total_count": "number"
}
```

**`GET /api/v1/pfz/{id}`** — single zone detail, same object shape, `404 ORCA_API_ERR_NOT_FOUND` if absent.

**Example request:** `GET /api/v1/pfz?bbox=76.5,7.5,78.5,9.5&active_only=true`

### 2.9 Evidence

Exposes the Evidence Grounding Records (`EVIDENCE_AND_CONFLICT_FRAMEWORK.md` Part A / `DATABASE_SCHEMA.md` §2.8) — this is what powers explainability drill-down in the UI.

**`GET /api/v1/evidence/{id}`**
- **Auth:** `authenticated` · **Rate limit:** `authenticated-read`
- **Response** (`200 OK`):
```json
{
  "id": "uuid",
  "source": "string",
  "dataset": "string",
  "parameter": "string",
  "value": "string",
  "unit": "string | null",
  "location": { "id": "uuid", "canonical_name": "string" } ,
  "observed_at": "string (ISO 8601)",
  "quality": "enum[verified, provisional, estimated, flagged]",
  "retrieval_method": "enum[api_call, database_query, feed_subscription, calculation, document_retrieval]",
  "reliability_tier": "integer (1-4)",
  "agent_output_id": "uuid"
}
```
- **Errors:** `404 ORCA_API_ERR_NOT_FOUND` if the id doesn't exist; `403 ORCA_API_ERR_FORBIDDEN` if the evidence belongs to a request the caller doesn't own.

**`GET /api/v1/evidence?recommendation_id={uuid}`**
- Returns the full evidence set backing one recommendation — i.e., `recommendations.citations` resolved to full records.
- **Response:** `{ "data": [ <same object shape as above> ], "next_cursor": "string | null" }`, cursor pagination per §1.3.

**Example request:** `GET /api/v1/evidence?recommendation_id=5c2e6a3e-2b1d-4f2a-9c3d-1a2b3c4d5e6f`

### 2.10 Agent Status

Two distinct needs, both under this heading:

**(a) `GET /api/v1/agents`** — static capability listing (which agents exist, their declared scope) for documentation/UI purposes.
- **Auth:** `public` · **Rate limit:** `public-read`
- **Response:**
```json
{
  "data": [
    { "agent_id": "ocean", "purpose": "string", "forbidden_responsibilities": ["string"], "timeout_ms": 8000 }
  ]
}
```

**(b) `GET /api/v1/agents/status`** — live operational health (internal monitoring).
- **Auth:** `internal` · **Rate limit:** `internal`
- **Response:**
```json
{
  "data": [
    { "agent_id": "ocean", "status": "enum[healthy, degraded, down]", "avg_latency_ms_last_15m": "number", "error_rate_last_15m": "number" }
  ]
}
```

**(c) `GET /api/v1/queries/{request_id}/agents`** — per-request execution trace: which agents ran, in what order, their individual envelope status. Backs `agent_runs` (`DATABASE_SCHEMA.md` §2.6) filtered by `request_id`.
- **Auth:** `authenticated`, caller must own the `request_id` · **Rate limit:** `authenticated-read`
- **Response:**
```json
{
  "data": [
    {
      "agent_id": "enum[...]",
      "run_id": "uuid",
      "status": "enum[ok, partial, error]",
      "confidence_level": "enum[high, medium, low] | null",
      "started_at": "string (ISO 8601)",
      "finished_at": "string (ISO 8601) | null",
      "warnings": ["object"],
      "errors": ["object"]
    }
  ]
}
```
- **Errors:** `404 ORCA_API_ERR_NOT_FOUND` if `request_id` unknown; `403 ORCA_API_ERR_FORBIDDEN` if not owned by caller.

### 2.12 Map Data

**`GET /api/v1/map`** — aggregated GeoJSON for map rendering, combining whichever layers are requested (observations, PFZ, advisories) within a bounding box. This is the one endpoint that returns `application/geo+json` rather than plain JSON, built with `ST_AsGeoJSON` over the relevant PostGIS columns.

- **Auth:** `public` · **Rate limit:** `public-read`

**Request (query params)**
| Param | Type | Required | Notes |
|---|---|---|---|
| `bbox` | `minLon,minLat,maxLon,maxLat` | yes | max area capped (e.g. 10° × 10°) to bound response size |
| `layers` | comma-separated enum | yes | any of `sst, chlorophyll, currents, waves, wind, pfz, safety_advisories` |
| `at` | ISO 8601 | no, default now | "as of" time — returns latest reading per location at or before this time |
| `zoom` | integer | no | used server-side to decide observation density/thinning at low zoom levels |

**Response schema** (`200 OK`, `application/geo+json`)
```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": { "type": "Point", "coordinates": [77.55, 8.08] },
      "properties": {
        "layer": "enum[sst, chlorophyll, currents, waves, wind, pfz, safety_advisories]",
        "value": "number | object",
        "unit": "string | null",
        "observed_at": "string (ISO 8601)",
        "quality": "enum[verified, provisional, estimated, flagged]"
      }
    }
  ]
}
```
`pfz`/`safety_advisories` features use `Polygon`/`MultiPolygon` geometries instead of `Point`.

**Validation:** `bbox` required and area-capped; `layers` must be non-empty and all values known.

**Errors**
| Status | Code | Condition |
|---|---|---|
| 400 | `ORCA_API_ERR_VALIDATION` | Missing/oversized `bbox`, unknown `layers` value |
| 429 | `ORCA_API_ERR_RATE_LIMIT` | — |

**Pagination:** not paginated — bounded instead by the `bbox` area cap and server-side zoom-based thinning, which is the appropriate control for a spatial payload rather than a cursor/offset.

**Example request:** `GET /api/v1/map?bbox=76.5,7.5,78.5,9.5&layers=sst,pfz,safety_advisories`

## 3. How This API Supports the Agent Architecture

- **`POST /query`** is the only endpoint that invokes the Coordinator and full agent pipeline — every other endpoint reads data the pipeline has already produced and persisted (`marine_observations`, `evidence`, `recommendations`, `agent_runs`), keeping read traffic cheap and the expensive multi-agent path isolated behind its own stricter rate-limit tier.
- **Observation endpoints (§2.2–2.7)** map directly onto Ocean Agent's and Ecosystem Agent's `OUTPUT SCHEMA` variable/value/unit shape (`AGENT_CONTRACTS.md` §1–2), so the API never needs a translation layer between what an agent produces and what it serves.
- **`/pfz`** mirrors the Fisheries/Ecosystem-adjacent derived-zone concept from `DATABASE_SCHEMA.md` §2.4, keeping PFZ's status as a *derived conclusion* (not a raw observation) visible in the API shape too (`basis_parameters`, `issuing_source`).
- **`/evidence`** exposes exactly the nine-field Evidence Grounding Record from `EVIDENCE_AND_CONFLICT_FRAMEWORK.md` Part A — this is what lets the frontend build genuine citation drill-down instead of a generic "sources" footer.
- **`/agents` and `/queries/{request_id}/agents`** expose the execution graph and per-agent envelope status defined in `AGENT_CONTRACTS.md` §0 and `agent_runs`/`agent_outputs`, giving the UI (and Human Review Gates in `WORKFLOW.md`) a way to see *which* agent produced or blocked a given claim.
- **`/recommendations`** exposes the Coordinator's gated output exactly as `REASONING_FRAMEWORK.md` §10 defines it — `recommendation_text` and `blocked_reason` are mutually exclusive-by-constraint at the database level (`DATABASE_SCHEMA.md` §2.9's `recommendation_requires_reason` check), and the API surfaces that same guarantee rather than allowing a client to ever see an unexplained empty answer.
- **`/map`** is the one place multiple agents' outputs are spatially composited for a single view, but it composites already-computed, already-verified data — it does not itself perform reasoning, conflict resolution, or confidence computation; those remain exclusively the pipeline's job.

## 4. Versioning & Deprecation

- All endpoints are prefixed `/v1`. Breaking changes ship as `/v2`; both are supported in parallel for a defined deprecation window before `/v1` is retired.
- Non-breaking additions (new optional fields, new enum values) do not bump the version, but are documented in a changelog referenced from this document.
- Any schema change to a response object here requires the same Human Review Gate as a database schema change (`WORKFLOW.md` § Human Review Gates), since the two are directly coupled.
